# PXP 自动待避强制验收清单

上位规范：仓库根目录 `AGENTS.md`。本清单适用于每次 PXP 开发任务结束，不限于修改自动待避代码的任务。

## 执行顺序与证据

1. 完整编译并运行基础单元测试，记录构建身份与命令。
2. 运行自动待避核心原生行驶回归；先核实进线、停车、全部快车通过、恢复的完整阶段，发现阻断性回归立即优先处理。
3. 重放当前问题存档并运行任务专项测试，固定输入副本及校验值，不覆盖用户原文件。
4. 根据修改范围执行双制动模式、保存重载、服务器与至少两个客户端的同步及性能检查。
5. 按十项固定状态报告最终结果。不能自动验证时明确“未验证”，列出人工步骤。

现有 Windows/Ninja 驱动：

```powershell
python regression/automatic_yield/run.py --build-dir build-win64 --baseset <实际基础图形目录> --output <本次独立输出目录>
python regression/automatic_yield/run.py --build-dir build-win64 --baseset <实际基础图形目录> --output <本次常规制动输出目录> --braking 0
```

上述驱动是入口，不代表清单所有项目已实现。必须读取当前模式及断言，确认实际覆盖，不能仅统计 PASS 数量。其他平台使用项目现有构建方式；无法运行时注明原因。

## 每次填写的矩阵

| 项目 | 必须观察的真实事件 | 当前任务状态及证据 |
| --- | --- | --- |
| 进入待避线 | 合法空位可达，慢车实际进线，车尾不占关键道岔 | 待填写 |
| 进入后保持等待 | 正确出口零速；等待期间不预留穿过受控出口，不直接驶出 | 待填写 |
| 连续多列快车 | 等待第一列及后续仍冲突的列车，逐辆出清后释放 | 待填写 |
| 快车优先不停通过 | 安全可行的独立正线路径、实际移动，不被慢车抢占 | 待填写 |
| 正常出线 | 全部相关冲突解除后恢复移动、离区、释放认领 | 待填写 |
| 多正线信号机 | 串联控制不误作平行道路；多出口信号持续执行等待 | 待填写 |
| 合流与分流 | 不同入口共享、独立分流、后续再合流的实际冲突 | 待填写 |
| 不同车站布局 | 普通、站台、混合、非对称、多入口出口各自记录 | 待填写 |

| PBS 与联机 | 原生预留安全、满线疏解、连挂、保存加载、三端状态一致 | 待填写 |

## 准确速度与扩展场景

至少维护 100→200 和 100→连续 160／200／250 的真实运行输入。记录实际设计速度及检测上限，不能把接近速度的原版机车当成准确速度，不能强改运行速度或停车状态来通过。既有修改引擎规格的满线隔离用例不替代该核心要求。

还须覆盖长距离目标、远处接近列车、停站前后目标切换、晚到快车、装卸、不同公司、前／尾／预留登记、满线安全腾位、保存等待状态后加载，以及调度修改、改道、删除、手动取消登记后的正确生命周期。必要时增加对应模式与日志断言。

## 无法自动验证时的人工步骤

1. 在启用自动待避的副本中，用真实设计速度分别为 100、160、200、250 的车辆搭建一正线一侧线及同一路签的四项控制点。
2. 启动慢车和跟随快车，记录进侧线、全列清空入口道岔、在出口停车、每列快车实际通过、最后车尾出清及慢车恢复的顺序；在等待中保存重载。
3. 分别换成全站台、普通、混合、非对称及多入口出口布局，增加串联正线及出口信号，测试汇合、分流和再汇合。
4. 运行中新增一条可达侧线／连接道岔，再安全删除或改接空闲支线；分别在有、无旧合法预留时观察候选与实际选路。不得人工非法清除预留强迫选新路。
5. 使侧线满载，观察安全腾位和恢复；用同一构建开本机服务器与两个客户端，重放保存点并比较状态。记录未覆盖项及具体失败事件。

人工步骤仅供执行，不等于已经验证；未实际执行的项目仍标记“未验证”。

## 2026-10-25 增补：停站支线与满线腾位

默认原生矩阵增加 `stock-full-fastest`、`stock-full-closest`、`stock-full-near`、`stock-full-long-block`、`stock-full-long-train`。正向用例必须验证最快合格占用车离开、请求车进侧线停车、快车通过时保持零速、最终恢复及认领释放；快车近、后续 PBS 区间过长的反例不得强行腾位。后续信号间隔必须容纳整个出发编组，不能把通过 PXP 清除点当成已腾空原生 PBS 区间。

平台可达性、站台容量疏解、未知邻近进路和有效保存依赖均保留独立测试。修改夹具原生区间或准确速度时必须说明原因，原版 112 或改过规格的 100 不得冒充准确 100 的专用原生场景。

本轮结果、未验证范围及真实玩家 294～297 行驶事件见 `docs/pxp-yield-207-297-turnover-20261025.zh-CN.md`。207 存档已越过可分入侧线的入口，不能把修复后别的经过当成已经还原其历史入站决策。

## 2026-10-25 增补：空位优先、远目标准入与新建股道

后续验收见 `docs/pxp-yield-free-sidings-20261025.zh-CN.md`，覆盖并更新上文旧报告的准确速度未验证范围。

- `normal-free-first`：空位优先于满线排序；快车临时失去接近预留时，慢车已确认的等待依赖不能消失。
- `far-empty-first`：不可达首候选不能越过区域出清点耗尽搜索，遗漏第二条空侧线。
- `far-multi-outlet`：远目标和不同出口分别验证；正向准入不能错误要求所有无关分支只有一个出口。
- `layout-new-first/second/third/platform`：新建普通、站台、第二、第三条非对称侧线，必须实际进线、停车、等快车出清后恢复；旧线受阻或移除不能被当作新线使用成功。
- `grf-basic/grf-200/grf-160-250/grf-consecutive`：使用真实 2cc Trains in NML 3.2，分别验证 100→160、100→200、160→250、100→连续 160/200/250。两制动模式、两种标记配置及保存重载共 32 次；构建和重载均断言实际设计速度及正功率。
- 不允许把 GRF 被禁用、未登记到快车、快车已在慢车停车前通过的夹具错误报告为正确完整待避。发车时间可以建立有效测试前提，但不得降低进线、零速保持、逐车通过和出线断言。
- 本地 1024 轨道节点预算与新增的每评估最多 128 个原生分段节点分别记录。只读原生查询禁用局部缓存，并测试单客户端预热缓存后仍与服务器和另一客户端一致。

真实问题存档仍须单独重放。207/205、309/310 的历史分岔决策已不在保存点中；相同真实车辆、调度和原站场的原生克隆运行属于等价复现，必须明确标注，不能冒充历史录像。


## 2026-10-26 增补：合流与分流同时存在

- 默认矩阵包含同站先合后分、分后再合、三入口合流、串联正线信号、侧线内普通 PBS 及停站后合流再分流。共享冲突应完整停车、等全部实际车尾并恢复；独立进路应同时运行。
- `topology-merge3-signals` 是侧线中间 PBS 推迟首次出口认领导致不停车的真实阻断性回归，禁止删去 STOP／双快车通过／恢复断言。
- `stock-full-long-train` 和原站场 309／310 等价实车复现同时作为搜索预算回归门槛；新增方向预测不能饿死既有股道分配和满线安全腾位。
- `occupied-second/third/platform` 必须保持旧线真实车体占用，而非仅通过寻路禁止替代；新建线必须实际使用、完整停车并恢复。
- 演示存档的所有列车必须已启动，重载后禁止由驱动额外发车；以只观察的重放确认完整流程。
- 旧隐藏侧线入口标记与新出口式标记混用、共享旧入口分支到多个不同长度出口，不能冒充已完成通用兼容。该旧格式限制应单列说明，不能简单取最大长度或丢弃旧认领以通过。

## 2026-10-26 增补：混合站专项与单待避站保护

- 修改混合站之前固定单待避站合流、分流、多信号及满线基线；修复后逐项比较真实行驶结果及阶段计数，不能重写其冲突、优先级、PBS 或认领规则。
- `mixed-p1o1/p2o1/p1o2/p3o2` 各有普通待避与计划停站两类工况，站台使用既有显式标记。实际进入的股道类别、正常站务、全列停入、出口等待、快车实际通过及恢复均须验证。
- `mixed-outlet-conditional` 保留真实条件调令：当前站台可达和停站后的目标预测分开，后续未知不能单独否定当前停站；仍须证明实际第一出口。不得为通过测试手动跳过条件或改目标。
- `mixed-outlet-explicit/single-clear/change/blocked` 对照明确后续、单出口、停站期间原生命令改后续、真实禁止出口。已知目标不兼容或无合法物理出线时不得误收。不同站台各自独占不同出口的更强场景需单独实测，不能用共咽喉后分流冒充。
- `mixed-full` 保持原满线真实占用和腾位断言；元数据查询不得耗尽后续安全证明的预算。仅复用完整、公司与两组轨道兼容条件相同的几何信息，不能缓存占用、订单、PBS 或未知失败结果。
- 合并上游后须重新编译并执行上述验收，合并前的成功不能证明合并后正常。旧 v1/v2 手动连挂速度条件按用户已选上游规则关闭，读档后重设；新 v3 条件另作真实读档和保存检查。
