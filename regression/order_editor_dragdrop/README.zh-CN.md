# 独立调度表编辑器点击／拖放回归

此测试载入真实游戏，调用 `ShowOrderListEditor()`／`ShowOrdersWindow()` 创建正式 `OrdersWindow`，再发送真实 `OnClick()` 和 `OnDragDrop()` 回调。不会用模型函数代替原 GUI，也不修改生产编辑器源码。

## 已确认的问题

2026-10-27 的用户崩溃发生在独立调度表 8116（“喀什西向交路”）的第一条路点命令。同一行按下并松开鼠标会进入拖放结束处理；独立调度表的 `vehicle` 正常为 `nullptr`，旧代码却在快捷文本标签判断中调用 `vehicle->GetNumOrders()`，读取空地址偏移 `0x220`。读取发生在判断命令是否为标签之前，因此普通路点同样崩溃。

已用原始用户崩溃存档及不含额外 NewGRF 的原版车辆地图分别实际复现：窗口创建成功、点击回调返回、同一行拖放回调发生 `C0000005`，故障地址 `0x220`、`RAX=0`，指令起始字节均为 `48 8B 80 20 02 00 00 48 85 C0`，与用户日志一致。

最小生产修复使用已有的目标模式助手 `NumOrders()` 和 `OrderAt()`，使独立调度表与车辆调度都访问各自的有效目标。没有改变调度命令、车辆状态、存档格式或 PBS。

## 覆盖的实际回调

默认九个原版地图场景：

1. 独立调度表的一条路点命令，同一行点击／拖放。
2. 独立调度表的一条文本标签，同一行点击／拖放，必须打开原生文本编辑框。
3. 空调度表的结束行，同一行点击／拖放，仍保持空表。
4. 非空调度表的结束行，同一行点击／拖放，原命令保持不变。
5. 三条带不同文本的标签，实际将第一条拖至第三行，必须得到 `B、C、A`。
6. 选中命令后用原生命令删除该行，再结束拖放，不得访问旧命令或意外修改剩余命令。
7. 普通车辆调度窗口，同一行点击／拖放，内容保持不变。
8. 普通车辆的文本标签，快捷编辑仍打开原生文本框。
9. 其他公司的公开调度表，只读点击不能修改命令；该回调没有启动拖放，因此不人为发送游戏中不会产生的拖放事件。

可选第十项直接载入用户原始崩溃存档，检查真实 8116 调度表的一条路点并执行同一组回调。所有输入存档只读，每次运行前后校验 SHA256 相同；不会将修改后的测试状态保存回输入文件。

测试原生命令也遵守数据语义：标签文本在插入后通过 `MOF_LABEL_TEXT` 设置；跨公司原生命令结束后先恢复本地公司上下文，再发送本地 GUI 事件。

## 运行

适用于已有正式构建的 Windows/Ninja 环境。程序会复制生产对象快照并链接独立观察器，不覆盖正式可执行文件；记录观察器、输入源码、生产对象清单、GUI 对象和输入存档的哈希。

```powershell
python regression/order_editor_dragdrop/run.py --build-dir build-win64 --baseset <基础图形目录> --stock-save <原版车型且有公司的存档> --output <独立验证目录>
```

原版地图应有本地公司的列车及命令，并在 `(130,40)` 有可转换为路点的空闲直线轨道；本项目已验证的输入是 `tools/yield-early-route-20261027/driving-build14-0/two-through-exit/strict-waiting.sav`。这是测试夹具要求，不是生产修复中的地图坐标判断。

实际故障存档可增加 `--player-save <崩溃存档副本> --player-config <能够载入对应 NewGRF 的配置>`。该配置的父目录作为资源查找工作目录，不使用 `-Q` 跳过资源扫描。可用 `--modes waypoint-click,player-waypoint` 只运行两条最小路径。

负向复现使用 `--before-objects <旧对象快照目录> --expect-crash --modes waypoint-click,player-waypoint`，必须在实际回调中出现匹配的空地址偏移崩溃，才能计为负例复现成功；不能将其计入修复版功能通过数。

每个场景生成 `events.log`、`stderr.log`，总结果为 `results.json`。没有观察事件、初始化失败、错误命令结果、非预期崩溃或存档哈希变化均失败，不以空日志或启动退出码冒充成功。
