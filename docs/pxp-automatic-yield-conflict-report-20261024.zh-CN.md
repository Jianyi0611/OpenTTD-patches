# PXP 自动待避：共同冲突资源修复与验证记录

日期：2026-10-24。本地分支 `px-patch`，基础提交 `d5ec2f02dcdfe75f03ec97a6797c680eb1c2560e`。保留原有未提交修改；本轮未提交、推送或创建 PR。

## 结果与边界

修复不同入口的真实共享轨道竞争、不同出口前的交叉冲突、空闲停车股道被共享出口预留错误排除、已确认待避关系的维护与清理，并为满股道腾位增加保守的冲突清空风险评估。等待仍通过现有 Trace Restrict 的 Deny/Wait 执行，轨道安全许可仍由原生信号和 PBS 决定。

最终验证：448 项单元测试／42,663 条断言；72 次新增真实行驶或重载测试；42 次既有复合入口、站台和桥隧行驶回归；同机服务器加两个迟加入客户端的 87 组共同状态全部一致，车辆位置及路签索引错误均为 0。

**47 号在吕梁的历史故障未能从提供的时刻复现，不能宣称该具体事件已经验证修复。任意规模、任意复杂物理铁路网绝不死锁，也不在这些测试能够证明的范围内。**

## 根因与修改位置

主要修改在 `src/tracerestrict_overtaking.cpp`。下表描述本轮相对于任务开始时备份的变化，未把此前所有未提交修改重复计为本轮新增。

| 缺陷或风险 | 最小修复方向 | 函数 |
| --- | --- | --- |
| 依赖相同 Clear 或相同入口识别冲突，遗漏不同入口、不同出口前的交叉 | 比较有向轨道足迹及整列车体，区分未知、独立、同向共享和交叉资源 | `GetSplitRouteProof`、`FindCommonConflict`、`ClassifyYieldConflict` |
| 仅检查本区域路签，漏掉另一检测区域的竞争列车 | 有界查询邻近已配置区域，随后以实际轨道关系确认；不向其他区域路签添加成员 | `Participants`、`FollowingThreat`、`CrossingThreat` |
| 出口咽喉暂时被快车预留，连空的侧线停车空间也判为不可用 | 入线时分别证明完整停车空间和合法续行；实际开出时才要求出口当前空闲 | `FreeLane`、Main 分支、站台入线检查 |
| 多出口时反复搜索远处目标，预算在真正检查停车股道前耗尽 | 先复用已证明唯一的本地出口，再作有界目的地预测 | `FreeLane`、`ProveOutlet`、`GetGoalClearanceHint` |
| 轨道跟随跳过站台目标、或包含原生设置禁止的 90 度转弯 | 检查跳过的站台格，遵守保存的原生转弯规则 | `AutoYieldTrack`、`GetSplitRouteProof`、`GetGoalClearanceHint` |
| 进入侧线后，短暂路径未知导致待避关系消失 | 仅在正式认领后记录已确认目标；未知不清理有效关系 | `RememberYieldTargets`、`MustWait` |
| 满线腾位仅按速度或距离排序，未充分约束实际阻挡风险 | 验证精确替换股道，并估算车尾清空共享资源与快车到达资源的先后 | `TurnoverCost`、`Evacuation` |
| 选择更早的冲突点时，覆盖了另一共享点仍有快车车体的标记 | 汇总保持任一共享轨道的真实车体占用 | `FindCommonConflict` |
| 被删除列车留下孤立目标、多个区域形成已保存的等待依赖环 | 有界清理孤立关系；只对确认闭环且可安全预留出口的一辆车退回原生 PBS | `AutoYieldGameTick`、`SafeYieldCycleFallback` |
| 同一提交的不同本地修改版可能共用网络版本号 | 为本地运行源码差异生成稳定身份，拒绝旧身份混联 | `FindVersion.cmake`、`rev.cpp.in`、`GetNetworkRevisionString` |

`src/tests/train_decouple.cpp` 增加跨检测区域、共享出口预留与有效依赖环测试。部分旧测试补齐了真实外部目的地或足够的快车接近距离；没有通过删除停车断言或放宽实际行驶顺序掩盖失败。新增 `src/tests/test_network_revision.cpp` 检查网络身份拒绝行为。

## 冲突资源与通行许可

资源依据是实际地格上的轨道、运行方向、车辆兼容性、连续预留以及可证明的合法续行。相同轨道或同格不能同时使用的交叉轨道才是冲突，地理接近本身不是冲突证据。

先以原生已预留的连续前路解析道岔，必要时使用有界目标预测。整列车辆占用始终参与比较，车头离开交叉点不代表车尾已清空。完整且不相交的合法走廊可以确认独立；分岔、结构、限制条件或预算使路径无法证明时，保留未知。

未知不凭空新建强制等待；已经确认并保存的有效依赖不会仅因这次查询未知而消失。快车被删除、取消登记、改变路线并已证明独立，或整列通过相关资源后，才能解除对应依赖。

没有给整个车站建立总锁。PXP 保留的是每条认领股道的目标依赖，实际互斥持有者仍是原生轨道占用与 PBS 预留拥有者。PXP 不授予绕过原生信号的许可。对于不同出口前的交叉，相关慢车可在交叉出清后放行，无须等待快车经过与它无关的下游清除信号。

## 满股道时的选择

1. 先检查每条候选股道的入口、完整停车段、列车长度、真实占用、其他车辆预留、合法出口及目的地兼容性。
2. 空闲侧线能停车时，不能因为共用出口暂时被占用而把它当成已满。
3. 需要腾位时，证明被选车辆可以依原生规则驶出，且腾出的**这条**股道能被**这辆**到达列车使用；假设检查只忽略被选离开车辆自身，不删除任何真实预留。
4. 优先复用正面证明的“能在快车前清空”结果；否则比较到最后共享资源的离场估计与快车到首个共享资源的最早到达估计。停止车辆加入起步余量、列车长度及额外安全距离。未知风险不许可腾位。
5. 对安全候选按成本及原有规则选择；停站需求优先释放适合的站台，正常装卸和连接工作不被强行中断。同速度时保留站台、客货及稳定车辆 ID 的确定性比较。
6. 没有安全方案时继续使用原生信号／寻路，条件改变后重评估，不以强制超时闯出解决堵车。

这些估计是保守整数启发式，不是逐帧精确加速仿真，也不构成任意场景最优调度的数学证明。

实际 100／160／200 测试使用原生建造的三列车。160 占满唯一侧线，100 接近，200 从另一入口驶来。远车测试中，160 在 tick 1999 开始离开，2384 车尾出清；100 随后进入并在侧线停车，200 通过时仍停，最后恢复行驶。近车测试明确断言：200 尚未通过时，160 不得开始离开；测试通过。

## 真实行驶测试

测试脚本：`regression/automatic_yield/run.py`。它只替换独立测试程序的地图构造／观察入口，行驶、加速、信号、路径预留和待避求值均使用生产游戏代码，不模拟列车移动或伪造待避决策。

| 场景 | 验证内容 |
| --- | --- |
| 一慢一快、显式侧线入口／仅侧线出口 | 识别冲突 → 入侧线 → 出口前真实速度 0 → 快车通过期间持续停止 → 出清后恢复 → 认领释放 |
| 传统／真实制动 | 两种制动模型分别完成 36 次，共 72 次 |
| 临时红灯、未知路线 | 已确认关系持续，出口后无越界预留；最终可恢复 |
| 两列快车 | 两车通过时均观察到慢车仍停止，最后可放行 |
| 车头／车尾登记 | 实际通过检测点后参与，非直接在测试函数中返回假登记 |
| 删除、取消登记、变更路线 | 清理无效依赖，已提交分流路线不再错误等待旧出口 |
| 不同出口且不相交 | 无错误侧线停车，独立路径保持运行 |
| 不同出口前有实际交叉 | 慢车真实等待，快车整列清空相关交叉后释放 |
| 交叉快车属于另一检测路签 | 识别跨区域竞争，不擅自改变另一来源路签归属 |
| 满侧线、远／近快车 | 安全腾位与禁止插入两种相反情形均有运行断言 |
| 等待存档重载 | basic、red、unknown、two 各含重载后继续等待和恢复 |
| 既有复合入口、普通股道／站台／混合、桥隧 | 42 次原生运行或重载通过 |
| 依赖环及被占用出口 | 单元测试确认稳定选择、只在正面安全证明后回退 PBS；堵塞时保留保护 |

基础真实制动、仅出口场景日志：`CONFLICT 753`、`ENTER 1006`、`STOP 1559 targets=1`、`CLEAR 1729`；最终 `hold_ticks=180`、`pass_while_stopped=47`、`released=1`、`slots_released=1`。每个测试在缺少真实停车、提前驶出、越过被控出口预留或认领残留时会失败。

交叉及跨路签测试同样检查快车通过期间慢车速度为 0；释放判据使用车体是否仍在交叉格，不能只检查“快车已过车站”。

满股道测试的 100 km/h 引擎规格在构造车辆前设置，是测试专用输入，不在每帧修改速度。该规格不由普通存档序列化，因此满股道场景没有重载变体，生成地图不作为可移植演示存档发布。

## 候选股道与放行日志

`yapf=7` 下输出区域、车辆 ID、候选信号、等待分类、已保存目标、路径查询余量和拒绝类别。类别包括认领占用、标记缺失、站台偏好、停车长度不足、入口或冲突预留、出口不可用、目的出口未知、不适合的替换入口／出口、已有优先列车通过、腾位风险未知或过高。腾位计算分支还输出资源及清空／到达整数估计。

本轮候选诊断运行记录了 83 次 `rejected=claimed` 和 93 次 `wait-conflict`，同时实际满股道行驶断言通过。这份运行没有触发每一个拒绝类别，不能将零次出现的类别宣称为已经实测覆盖。日志默认关闭，以免玩家正常运行产生大量 I/O。

## 联机、存档与性能

最终同机联机：服务器和两个客户端全部持续连接，第二个客户端迟加入，接收已经停车并保存待避关系的双检测区域地图；三端 87 组共同采样状态一致，差异 0、索引错误 0。采样包括游戏 tick、随机状态、车辆位置／速度／状态、路签成员和标记、有限地图与路径预留哈希。合成地图全部位于采样范围内；这不是大型玩家地图的无限时长多机器压力测试。

本地源码身份测试验证内容变更会变更身份、测试文件不改变运行身份、恢复文件后身份恢复，以及 6／7 字段源码版本元数据的读取。网络单元测试确认旧提交哈希身份不会混入新的修改版。同一局的服务器和客户端应使用同一构建；这不是新网络包格式，也没有改写原 Git 提交 ID。

本轮沿用已存在的 `pxp_automatic_yield` 扩展版本 11，没有再增加持久字段或存档版本。既有功能与迁移代码保留；旧程序能否读取 v11 文件仍取决于它是否实现此扩展，不能保证倒向兼容。

## 未解决及未验证范围

- 47 号原故障时刻未复现；需要故障前且包含对应快车交通的存档，才能验收那一次事件。
- 每次求值最多 1,024 探索节点；单路线足迹最多 256 节点、最多 16 参与者／16 股道／16 检测点。跨区域候选查询最多 8 个邻近区域；空间索引只是缩小搜索范围，过大或过远的组合可能退回原生规则。
- 遇到不能可靠展开的桥隧、未知分岔或预算耗尽，不新建未经证明的强制等待；已有有效目标遇到未知则保留。桥隧登记已有运行回归，但任意桥隧组合中的共享资源预测并非全部支持。
- 已保存依赖环有单元验证，但未完成任意多区物理闭环铁路网的真实行驶穷举。原生出路被占用时不会强制解除安全保护。
- 持续满载且始终没有安全空隙时，不保证有限等待时间；没有引入可能阻挡快车的强制饥饿超时许可。
- 其他用户寻路限制若在自动待避指令之后显式取消 Deny/Wait，仍能覆盖结果；没有擅自改变现有程序解释器的顺序语义。
- 已通过测试不等于对所有玩家自由建设的站场、所有 NewGRF 和所有联机操作顺序提供形式化无死锁／无不同步证明。
