# 多出口原生提前选路验证记录

基线：`080f9d580e4a2c42c4b65c6c010490ef5a8df966`，备份分支 `backup/pxp-before-early-route-20261027-212901`。本任务只在至少两个车尾清除点的区域启用提前选路。原有单出口待避优先级、满线放行、路签生命周期与连挂解挂策略没有重写。

## 实际选路与 PBS

`YapfTrainPlanRoute` 使用原生目标、代价、合法轨道方向和限制程序，导出原生成功搜索选中的轨道序列。目标仍是当前调度目的地；出口由选中路径经过的车尾清除点确定，并非把出口信号替代调度目标。失败、预算不足或不支持的反向返回明确状态，不把部分建议路线当成成功。

停站列车分别搜索当前站台和可安全读取的后续目标；在多个站台之间使用原生搜索选择可完成当前停站、并可到达已知后续目标的站台。条件、路签、计数器和执行计划等副作用不提前执行。未知后续仅保存已成功通过检测点的区域上下文；原生命令实际执行后，从当前合法预留末端重新规划。

计划不等于预留。一次实际预留成功才发布状态；尚未完整预约的真实计划和实际采用的轨道序列分别记录。后续 PBS 搜索通过原生代价选择符合当前有效计划的合法路径，独立必经点状态保证经过所选出口。原有无必经点搜索的节点和哈希类型不变。

实际待避限制禁止原选站台时，记录这一次搜索中的有向禁止点，在新一次搜索中重选，禁止中途改变同一次 A* 的允许图。未知后续但当前停站及物理出线已证明可行时，允许替换原本未确定出口的站台；已有确定出口不能因查询暂时不完整而被清除。

## 状态与同步

- 当前及后续命令、被跳过的控制流、编组及货物语义、方向、标记配置和轨道变更均参与有效性校验。变更后的合法重选保留原有已提交 PBS 前缀。
- 嵌套原生预留切换到无关调度命令时，禁止读取旧冲突证明或发布不匹配的计划。
- 检测点和清除点的连续预留证明同时校验轨道方向。真实车尾清除、手动取消登记仍负责清理区域上下文。
