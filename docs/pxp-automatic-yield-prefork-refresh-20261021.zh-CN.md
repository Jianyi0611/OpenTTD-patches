# 分岔前待避复核修复（212 号，2026-10-21）

## 原因和复现

原始问题存档中，210 号占用普通待避股道，站台股道空闲，212 号最大速度 120，后方 213 号检测速度 160。212 号需要待避且当时可进入空站台，但已预留的直行段终点在分岔之后、正线标记之前。下一次正线回调发生时，车头已经越过分岔，此时可用股道证明失败，列车继续通过正线。

这不是简单的站台不可用。单独刷新预留能绕过当前实例，但不能解决后续列车的同类问题。

## 代码修复

在正常模拟循环中，对已登记的活动列车分散进行复核，每辆每 8 个保存的模拟刻最多一次。资格及判断均由存档状态、车辆编号和线路计算；不在读档、路径试算或界面刷新中修改预留。

只有确认以下条件才请求重算：当前命令是普通车站、路点或回库命令；车辆未手停、未强制闯灯、未换向或等待同向解挂离开；没有既有待避股道认领；其自身预留的末端仍通向正线标记，但从该末端已不能进入待避出口；车头当前位置仍有可达、可容纳、无其他车辆或预留阻挡且具备出清通路的股道；并且原有优先级逻辑要求该车待避。

通过后，仅调用现有 FreeTrainTrackReservation 与 TryPathReserve，沿用 PBS 的预留、占用保护、路签事务回滚、前瞻更新及失败停车处理；没有替换 YAPF/PBS 选路算法。已进入侧线或已经越过可转入分岔的车辆不进行这项重新预留。

每个区域仍限 16 个参与者，复核共享原有最多 1024 个探测节点预算；超过预算不强行重算。没有新增存档字段。
