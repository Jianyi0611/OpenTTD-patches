# 73／183 停车回归、连续快车及动态站场修复

## 确认的原因及最小修复

1. **进入侧线却不停车**：`src/tracerestrict_overtaking.cpp` 的 `GetMainApproaches` 将“本地站台停靠后的出口预测”误用于普通远距离车站调度。提交侧线认领时，自身正线接近关系被丢弃；整段远目标查询不完整，已确认的跟随快车未保存为等待目标。修复将特殊分支限定为正在服务／确实即将在本地站台停靠的情况，保留普通远目标的原有接近关系。没有改寻路惩罚或强制停车。
2. **第一列通过后漏掉晚到快车**：补充真实长接近区间测试发现，等候期间新来的快车可能超出局部路径足迹范围。`RememberYieldTargets` 在已停车、只有一个正线／出清出口、对方已经登记且能明确证明到达该正线时，复用实际接近及共同出口证明，保存后续依赖。多出口仍要求实际共享冲突证明，不把未知一律当冲突。`MergeClearanceDistance` 在未完成的强制目标处停止，不能跳过中间停站预测后续路线。
3. **改变信号方向后元数据过期**：原生信号修改命令没有通知 PXP 更新方向。新增 `AutoYieldSignalChanged`，在 `CmdBuildSingleSignal`／`CmdRemoveSingleSignal` 成功执行后、原生重新预留前更新相关控制点，包括模拟桥隧两端。没有用各客户端可能不同的本地 YAPF 缓存计数驱动已保存状态。
4. **断开的空侧线仍保留旧认领**：`AutoYieldGameTick` 现有 64 tick 清理中增加 `ProvenOrphanLane`。只有证明车体已不在独占停车段、没有出口预留、本车没有通往该出口的预留、当前前进路径已无法到达原股道，才释放该逻辑认领及对应依赖。保留源路签。车尾、站台中间瓦片、未知桥隧、搜索预算不足或仍可达时保留；不动 PBS、列车状态和调度。

几何查询读取当前轨道，未发现需要新增长期拓扑缓存。原生轨道命令已有 YAPF 更新；仍然合法的旧路径可以继续使用。新增道岔不保证原生寻路必选新路。真实制动会拒绝拆除行驶列车的预留路线，本轮保留并测试这一限制。

## 保留与边界

自动待避存档扩展仍为 v11，没有新增持久字段或更改 PXP 连挂／检查点功能。本轮未修改原生寻路算法、惩罚、快慢车设计速度，也未强制设置玩家列车停车状态或任意清除其预留。

**准确 100→200、100→连续 160／200／250 的专用真实车辆输入未验证**：现有便携基础用例实际为原版 112 km/h，stream 实际为 112／160／200／264（250 检测上限）。修改引擎规格的旧满线隔离用例不替代该要求。可执行人工步骤见 `regression/automatic_yield/ACCEPTANCE.zh-CN.md`：选用真实设计速度匹配的车辆，分别验证整列进线、停车、多辆车尾出清、恢复及等待重载；未执行前不能标记准确速度场景通过。

原反馈没有动态编辑前后两份历史存档，无法还原当时每一次旧道岔选择。当前原始存档及动态构造回归证明了本次修复范围，不代表地图上每个设施均已单独完成一轮追越，也不承诺任意自由站场或持续饱和交通永不死锁。性能采样为同存档、相同诊断频率各一次，不等于完整帧率基准或长期联机压力测试。
