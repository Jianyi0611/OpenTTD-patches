# 检测速度上限、同速载客优先与 5% 默认值

接近检测点新增“检测上限”，默认采用该信号所在轨道类型的限速，也可选择“手动输入”。新建或从其他角色切换为检测点时，默认速度差为 5%；已有检测点保存的比例不变。

## 运行规则

- 比较速度取列车最高速度与检测上限中的较小值，仅影响自动待避，不改变实际车速、实际限速、寻路算法或 PBS。
- 铁轨限速为 0 表示无限速，不封顶。手动输入正数，按当前游戏速度单位显示和换算，命令与存档保存统一内部速度值。
- 同一路签有多个检测点时，采用最低有效上限和最高速度差比例，全组规则一致，避免因进入位置不同而互相等待。
- 封顶后速度不同，继续按速度差比例判断；较慢客车不压过较快货车。封顶后同速，实际载有乘客的列车额外优先。空客车无额外优先，两车均载客或均不载客时不额外制造同速待避。
- 载客识别检查整列车，包括后方及铰接车厢，使用 NewGRF 的乘客货物类别；普通货物、邮件不算乘客。装卸改变载客情况后，下次判断重新读取。
- 快慢车判断、稀缺股道排序、出口等待、腾位来车及离开车辆的选择，统一使用封顶和同速载客规则。仍保留股道独占、可达性、容车长度、实际预留和车尾出清保护，不打断停站、装卸、解挂或连接任务。

## 实现与兼容

检测上限使用双字指令第二字的低 16 位，0 为铁轨默认；高 16 位仍是速度差比例。非检测角色不读取上限。默认轨限实时按信号所在 track 读取，兼容同格不同轨道类型及改造后限速变化。

旧 v1～v7 的低位是废弃距离。读档在验证程序前清除检测指令的旧距离位，保留比例、路签及角色，避免旧值 100 或 65535 被误当作速度。新存档特性 v8，仍可读取 v1～v7；旧程序拒绝加载新存档，联机需统一新版。

载客状态只缓存于一次判断，最多 16 个成员，不增加车辆持久字段、随机调用或本机 UI 依赖。原每次 1024 节点、单搜索 256 节点的探路预算保留。

检查中还修复了编辑指令插入或删除第二字后继续使用原 vector 迭代器的隐患：操作后重新取得迭代器再归一化默认值。没有据此认定历史崩溃的根因。

## 验证

- Windows 全部 383 项测试、11664 个断言通过，覆盖上限边界、无限速、实时轨限、混合轨道类型、多点、复制与编辑、角色转换、5% 默认值、速度单位、旧距离迁移和载客变化等。
- 实际地图对照：慢车最高速度 112、后车 200，上限均为 100。两车为空客车时，慢车未进侧线，第 2164 游戏刻完成通过；后车带一名乘客时，慢车进入侧线停车，后车通过后离开，第 2221 游戏刻完成。均正常退出，具体路径仍由原寻路决定。
- 五种旧 v6 快照（全普通、全站台、混合、正常停站、高惩罚回退）及旧 v7 双正线快照加载运行通过，检查了进线、停车、后车车尾出清、前车继续。
- 简体与繁体实际格式化输出速度差 5% 和检测上限 160 千米/小时；没有新字符串参数不匹配告警。
- 本机服务器和两个客户端加载 v8 手动封顶及载客示例：83、78、77 个采样中，77 个共同采样全部一致，车辆位置索引异常为零，运行期间保持连接。检查车辆状态、路签认领、预留、随机数和同步校验。
- 联机采样覆盖最终速度与载客逻辑；后续编辑迭代器修正及角色默认值调整由命令回归和完整测试另行覆盖。没有进行长期公网测试。观测助手仅在 tools 中，发布程序没有观测钩子。
