# 荒山下行多接近点无法领取路签（2026-10-20）

## 根因

区域构建代码原来要求 `approach_count == 1`。同一普通路签放置两个接近检测点后，整组被判为无效；真实经过回调又依赖这个区域有效，因此远处和近处都无法登记。不存在“只选择最近检测点”的规则，也不是检测距离限制。

## 复现证据

工作区 00:48:35 的 `慢车无法等待.sav` 中原本只有一个荒山下行接近点 `(1253,3818)`，容量 10、总开关开启，57 号车可以正常领取。

在独立进程的存档内存副本中，将现有信号 `(1259,3818)` 增加为同路签的第二接近点，没有更改轨道、信号类型或原存档文件：

- 修复前：区域失效；57 号车在第 32 刻经过第一点、第 135 刻经过第二点，均未登记。
- 修复后：区域有效；第一点登记，经过第二点仍只有同一车辆的一条记录；继续运行至车尾通过清除点后正常退出。共运行 2500 刻并正常结束。

## 修复后的行为

- 每个路签支持 1～16 个接近点；保留原有一个正线控制点、一个车尾清除点及股道配置要求。
- 实际经过任一接近点即可登记，重复经过不会重复占容量。已经属于同一组的车辆经过后续检测点，不会被当成区外新车拒绝。
- 容量、公司权限、开关、信号方向与真实经过权限仍检查；寻路预测或临时事务不能提前登记。
- 实际登记与车尾清除独立于下游配置是否完整、区域缓存是否等待重建。配置有误时只保留成员记录，不启用未经验证的待避控制。
- 同组各接近点的百分比不同，统一使用最大值，避免结果随信号位置或遍历顺序变化；建议全部设为相同百分比。
- 没有恢复距离选项，没有修改 YAPF/PBS 算法。检测点数量设上限以保持每次查询的工作量有界。
