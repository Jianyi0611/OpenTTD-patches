# 2026-10-21：装载率统计性能优化与多核范围

## 实测瓶颈

用户反馈暂停后拖动地图明显流畅。对“慢车无法等待.sav”运行 2048 个游戏刻，不绘图、不播放音效，使用外部诊断副本测量模拟耗时。自动待避检查约 23 毫秒，占整段模拟约 0.1%，不是这份存档的主要耗时。

装载率查询为每节车厢调用 RVTransportGetPartCargoAmount，每次又扫描全地图车辆查找载运重量。即使没有载运车辆，也执行全局扫描。两轮基线中装载率统计分别耗时约 6.13、6.26 秒。

## 修改

新增整列车货量统计：每次查询只扫描一次全地图车辆，把属于这条物理车链的载运重量按承载车厢归集，再逐节换算并合计。普通装载率及指定货物装载率共用此计算。

单节查询与整列查询共用相同的吨位换算函数，保留逐车厢取整、容量封顶、零重量/无效货物处理，以及从物理链首统计的规则。使用调用内临时表，不引入跨刻缓存。装卸、改挂、承载对象变更后，下次查询立即读新状态。

未修改列车运动、寻路、PBS、待避优先级、货物装卸、存档结构、随机数或同步命令顺序。未关闭任何功能或降低模拟更新频率。

## 验证与性能

同一存档、相同编译器与诊断代码，各运行两轮 2048 游戏刻：

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 第一轮模拟耗时 | 19.171 秒 | 15.091 秒 |
| 第二轮模拟耗时 | 19.048 秒 | 14.611 秒 |
| 平均模拟耗时 | 19.110 秒 | 14.851 秒 |

模拟耗时降低约 22.3%。装载率统计修改后约 0.6 秒。这里测量的是无绘图的模拟计算时间，并非窗口 FPS；实际帧数还受视野、分辨率和绘图负载影响。

两轮各 32 个共同采样的车辆位置、速度、状态、路签、随机状态和模拟校验与基线完全相同。完整 396 项测试、12496 个断言通过，包含逐节取整与封顶、多货物过滤、其他承载列车排除、主控在链中、载运变化立即生效和既有待避/联机回归。

本机服务器与两个客户端短时联机：84、79、78 个采样，78 个共同游戏刻一致，车辆位置索引异常为零。测试脚本停止进程，不作为正常退出验证。不能据此宣称所有存档或长期公网运行均无问题。

## 多核支持与边界

当前游戏已有最多 8 个通用绘图工作线程，另外有后台存档和货流计算。车辆移动、预留和路签变更共享状态，不能直接把逐车更新任意拆成多个线程。本次保留已有线程机制，减少主线程重复计算；没有把车辆模拟改成并行执行，也没有通过增加线程数量制造更高 CPU 占用。

## 两条线路汇合

补测了两条接近线路汇合后共用正线控制点的配置：另一入口快车可以触发慢车进侧线；同速空车或手动停下的后车不会触发。正线控制点应位于待避分岔后的正线支路。

如果两条线路各自的正线控制点都在合流之前，现有逻辑可能将其视为独立正线，不能保证按合流后的前后关系安排待避。本次没有为这种布局新增汇流瓶颈识别。
