## 修复

1. 同一次主线判断复用接近列车顺序与已计算的空线结果，避免重复探路耗尽预算，导致入口与侧线出口作出不同的腾位判断。总预算仍为 1024、单路上限仍为 256。
2. 车头已越过出清点、车身仍跨在出清点上时，保留腾位关系。真实股道认领和路签仍由原有车尾出清事件释放。
3. 岔口路线证明区分本车、假定离开的列车、其他列车及未知归属的预留。本车试探的正线路线不再掩盖另一条可进入的侧线；只在只读证明中过滤，不删除任何真实预留。他车和未知归属的冲突仍阻止入线。
4. 等待腾位时，主线信号同时拒绝作为预留终点。否则先预留到岔后的正线信号，就已经选定正线，侧线空出后也无法在岔口正常改线。沿用现有 PBS 终点限制接口，没有修改 YAPF/PBS 寻路机制。

回归测试分别复现了预算失配、车头出清后过早遗忘、岔口本车预留误判，以及主线预留终点错误。修复前相关断言失败，修复后通过。

## 三种配置

| 配置 | 行为 |
| --- | --- |
| 全部普通待避线 | 使用可用、足够长且可安全进入的普通侧线，保留等待和腾位规则。 |
| 全部站台股道 | 在可用站台之间选择，保持正常停站、连接作业与待避等待。 |
| 普通待避线与站台混合 | 本站不停时优先可用普通股道，普通线不可用时允许安全站台回退；保留高数值惩罚回退规则。 |

以上三种均不能越过禁止进入、外车占用或冲突预留，不能强塞过短股道。没有安全可证明的入线方案时保守处理。站台作业不会被强制要求腾位，既有不可安全取消的路径继续受保护。没有新增存档字段或网络命令，保存特性保持 v6，联机使用同一构建。
