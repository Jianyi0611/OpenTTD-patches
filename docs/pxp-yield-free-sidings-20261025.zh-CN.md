# PXP 空侧线漏待避、提前出线与远目标准入修复

## 结论和验证边界

按要求先处理附件中的“空位优先于满线策略”，再完成 207/205、309/310、新建股道和连续快车专项。本轮修复适用于实际轨道查询，不含列车编号、车站坐标或固定道岔方向特例。正式程序已本地编译；没有提交、推送或创建 PR。

472 项单元测试、44,566 条断言通过；296 次本轮原生行驶／保存重载和 42 次既有复合入口、站台、桥梁回归通过。准确 100→200、160→250、100→连续 160/200/250 已使用真实车辆包验证，覆盖两种制动模式。

玩家原文件未改动。当前问题副本 `慢车无法等待.sav` SHA256 为 `5d1f441b65cfa08dbbea3d683d3fca28e691cc0ed9f8025a0148a32af338adac`，复制时修改时间为 2026-10-25 12:32:28。保存点中的 207/205 是另一趟回程，309 已经过原分岔并持有正线预留，无法从这一个保存点还原其历史决策。因此，下面区分原样重放和同车同站场的等价原生复现，不把后者冒充历史录像。

本地分支 `px-patch`，基准提交 `d5ec2f02dcdfe75f03ec97a6797c680eb1c2560e`。生产模拟代码身份：`c6413ba47fc2a1e984470586d853b796e413ebf1045ec9cf4403037ee91ec894`。保留工作开始时的其他未提交成果，备份位于本次诊断目录的 `before.patch` 和 `before/`。

## 根因与最小修复

| 故障环节 | 已确认的证据 | 修复 |
| --- | --- | --- |
| 候选股道搜索 | 第一个不可达候选继续搜到区域 Clear 之后，耗尽准入预算，第二条合法空线被遗漏；修复前对应回归 2 条断言失败 | `RouteToRole` 不跨本区域的 Clear 继续寻找入口／停车角色，保留其他候选的预算 |
| 正常待避决策 | `NeedsSiding` 在有空侧线时仍按满线的最近到达者排序，否决前方慢车；修复前 2 条断言失败 | 确认真实冲突后，正常空位准入优先；距离排序和满线例外仅供满线腾位 |
| 进入后不停车 | `normal-free-first` 中快车排队暂失接近 PBS，pending 登记被清除，随后慢车保存的等待依赖丢失；修复前 3 条断言失败 | `AwaitedPendingApproach` 保留已经被有效等待关系引用、且仍有正向接近证明的登记；停止、反向、删除或手动取消仍能释放，不凭空重新登记 |
| 309/310 股道准入 | 原站场两个候选都无认领、停车长度／普通信号检查可通过，`NeedsSiding=1`，但 `FreeSiding=0`；诊断为 `destination-outlet-unknown-or-incompatible` | `GetGoalClearanceHint` 区分“存在一条到显式目标的合法路径”和“所有可行路径只有一个出口”。股道准入只需前者，优先级预测仍保留后者；缓存按证明种类和要求的出口隔离 |
| 冲突后的预算分配 | 已确认需要待避，仍扫描其他无关的合流成员，把停车证明预算耗尽 | `NeedsSiding` 先验证是否确有可用平行正线；没有该替代路径时，首个真实冲突即足以进入正常准入，不再为同一结论穷尽无关成员 |
| 207/205 长编组及远站 | 实际停车段足够，远站在区域外约数百格；本地目标预测到达上限后，将合法侧线当成目的地未证明 | 先证明候选能到允许的首个 Clear，再对显式车站目标调用有界、只读的原生可达查询；不把正向结果当作唯一出口证明 |
| 满线例外 | 未来容量压力可能在仍有正常停车位置时触发腾位 | `Evacuation` 优先检查正常空位，预算未知不能授权可选腾位。保留正常停站的站台容量疏解和真正满线的安全评估 |

当前工作开始时包含未提交修改，无法仅凭 Git 提交号把每处回归唯一归因到某一次历史提交。本轮的“修复前”均指保留的工作起点实现，失败日志和对应源文件差异单独保存。

## 修改范围和安全约束

生产代码只增改 `src/tracerestrict_overtaking.cpp`、`src/pathfinder/yapf/yapf.h` 和 `src/pathfinder/yapf/yapf_rail.cpp`；另增补 `src/tests/train_decouple.cpp`、原生回归驱动、清单及本报告。工作区其余原有修改未覆盖。

新增 `YapfTrainCanReachStationBounded` 复用原生轨道跟随、目标和普通限制规则，仅读取可达性；不选择或提交列车进路，不预留轨道，不改列车、调度、随机状态。临时红灯不能被当成永久无法从停车股道抵达车站；真正出线仍走原有 PBS 申请及等待限制。

本地轨道查询仍共享每评估 1024 节点。新增原生查询每次最多 32 个分段节点，每评估共享最多 128 个分段节点，结果只缓存于当前评估；禁用原生分段缓存，防止有限预算的成功与否取决于各客户端的缓存历史。两类预算不同，不能合称“所有查询仍只有 1024 节点”。递归保护避免可达探测再次触发自动待避决策。

不增加存档字段、扩展版本或网络命令，不修改 PXP 连挂／解挂实现、速度匹配、原生寻路权重和信号安全。四项界面名称及选项保持原有配置：接近检测、正线控制、待避股道出口、车尾清除点；旧存档的显式入口仍参加兼容测试。

共同冲突继续按实际有向轨道、可行目标路径、真实车体及 PBS 预约证明，区分共享、独立和未知；不会因为同一区域或同一车站就锁住所有出口。保存的逐车等待依赖必须等待相应实际冲突资源出清，不能把快车车头经过车站当成所有慢车的放行条件。

真正满线时继续使用既有流程：沿真实冲突路径选择请求者；候选离线必须实际腾出能容纳请求车的股道；比较速度、站台作业、原生区间长度及快车预计到达风险。最快合格候选优先；距离过近、长区间无法及时出清、长编组或未知证明不能盲目放行。正常停站、等速远近、站台容量和闭环安全腾位的既有规则保留。

## 联机、性能及剩余范围

普通待避、远站多出口各启动本机服务器和两个客户端，实际修改轨道／信号后继续运行。每组 87 个共同采样、79 个修改后采样，车辆、随机状态、路签、PBS 及地图状态指纹差异 0，索引错误 0。远站组仅客户端 A 预热普通 YAPF 缓存，再将有界查询的结果／消耗与实际股道准入纳入比较，三端一致。测试结束由驱动结束自建进程，不将其描述为服务器正常交互退出测试。

同一玩家副本、相同诊断采样各 6000 刻的单次耗时：工作起点 36.282 秒，当前 36.718 秒，约增加 1.2%。包含读档、日志和系统负载，不是游戏 FPS 基准，也不作为提速证据。本轮增加的远站准入有明确预算和本次评估内缓存，没有每刻全图扫描。

尚未穷尽：任意玩家拓扑、超过现有每区 16 列车／16 股道保护范围的复杂区域、长期无限饱和交通、不同硬件的长期公网联机。远目标补充查询目前仅用于显式车站目标，超出预算或其他目标仍可能未知；未知不授权安全腾位，也不表示已证明永久不可达。当前通过的场景不能被解释为任意设计永不死锁。原保存点之前的历史经过仍未直接重现。
