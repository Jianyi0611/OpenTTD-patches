# 当前使用规则（2026-10-21）

- 接近检测改为成功预留经过检测点的路径时登记，不必等待车头实际经过；失败预留会回滚，入区前取消预留会周期清理待进入认领，驶入后仍由车尾清除点退出。新存档特性 v9，联机需统一新版。
- 自动待避路签无需公开也能由其他公司的列车自动领取，但仍须遵守共享铁路通行权限，路签配置编辑权限不变。详见 [预留登记与跨公司复核](pxp-automatic-yield-reservation-sharing-20261021.zh-CN.md)。
- 同速客货车让行仅对近距离跟随触发：客车车头与货车尾部最多相隔 16 格，按前向路线比较，不把相向或远处客车当作追赶者。速度确实更高的列车仍不增加检测距离限制。
- 普通短暂停站保留优先权，短暂卸空乘客不会立即放走待避车；满载、连接、长时间计划停站或本次停站达到 256 游戏刻后释放此保护，避免无限占线。腾位也遵守短停保护。
- 普通桥隧可参加只读通路证明；模拟信号桥隧要求全段无车且两端没有预留。真实行车与预留仍由 PBS 决定。详见 [近距离与河湾口复核](pxp-automatic-yield-proximity-stations-20261021.zh-CN.md)。

- 动作菜单统一为接近检测、正线控制、待避股道出口、车尾清除点；旧入口标记隐藏但兼容旧存档。已证明反向的快车不再使侧线等待，未知远车及正在通过的快车仍保留优先权。详见 [名称与同步检查](pxp-automatic-yield-labels-sync-20261020.zh-CN.md)。
- 全普通侧线、全站台及混合布局共用安全待避与腾位规则。等待腾位时不预先锁定岔后的正线终点；腾位关系保留到车尾出清，路线证明识别本车的岔口预留。详见 [德州待避修复](pxp-automatic-yield-dezhou-20261020.zh-CN.md)。
- 接近点不再因区内有侧线认领而封锁新车，保留容量检查。普通线不可用时，需要待避的慢车可使用安全空站台并忽略该站台标记程序的数值惩罚；显式禁止、等待及实际预留仍有效。详见 [王家与站台回退修复](pxp-automatic-yield-wangjia-20261020.zh-CN.md)。
- 待避股道可选择“普通股道/站台股道”；本站不停时优先可用普通股道，否则允许站台回退。停站及连接任务保留，站台作业不参与强制腾位或阻塞批次。详见 [站台股道](pxp-automatic-yield-platforms-20261020.zh-CN.md)。
- 侧线腾位仅在没有其他可用空线、来车能进入且能出清、不会抢在正在通过的快车前方时执行；只有选中的来车等待腾位。详见 [停车与侧线出线优化](pxp-automatic-yield-evacuation-20261020.zh-CN.md)。
- 同一普通列车路签关联接近检测、正线控制、待避股道出口、车尾清除点。支持 1～16 个正线控制点，共用一个车尾清除点；适合同方向多正线和共同出口的布局。独立上下行请使用不同路签。支持 1～16 个接近检测点，重复经过不会重复占容量；同组多点速度差不同则取最大值，建议设置一致。待避入口标记可省略。
- 仅接近检测设置最小速度差；已删除检测距离输入与距离筛选。旧存档的距离数值保留在原字段但不参与计算，也不显示。
- 已经越过检测点但尚未登记的旧车辆，需要以后重新预留经过检测点的路径；不会倒查并强行改动既有线路选择。
- 同一路签内的有效列车参与判断。远距离成员不会因为旧距离值或位置清理被自动排除。已登记且轨道检查尚未完成的远处列车按潜在后车处理；这不构成入线许可，实际入线仍须通过占用、预留和股道长度检查。
- 计算预算保留以避免卡顿：每个动作/条件共用 1024 个探测节点、单次局部路线证明最多 256 个节点；预算不足时不能据此强制进入股道。最多支持 16 个参与列车、16 条待避线，源路签容量应足够容纳参与列车，例如 16。
- 手动移除路签成员或清空整个源路签会释放对应隐藏股道认领；路签解除后该车待避条件失效。关闭开关仍允许车尾清理。
- 接近点的实际经过登记与车尾清除不依赖下游角色是否完整；出口配置有误时仍能记录成员，但自动待避控制保持停用。
- 新存档标记为 `pxp_automatic_yield` v8，保留 v1–v7 读取兼容；旧程序不能读取新版本，以免多正线、站台与多检测点规则不一致。多人联机应统一使用同一构建。

多正线按最近可达的正线控制点比较后车，不把两条正线各自的距离直接比较。另一条正线到共同清除点经占用、预留和普通限制检查可安全通行时，不强制慢车进入待避线；这不会强制寻路器选择该正线。待避出口仍保护同组正在通过的快车，直至车尾出清。详见 [多正线验证](pxp-automatic-yield-multiple-mains-20261020.zh-CN.md)。

接近检测点新增“检测上限”，默认采用该信号所在轨道类型的限速，也可选择“手动输入”。新建或从其他角色切换为检测点时，默认速度差为 5%；已有检测点保存的比例不变。 同组多点取最低上限，封顶后同速时实际载客优先。详见 [检测上限与载客优先](pxp-automatic-yield-speed-cap-20261020.zh-CN.md)。

## 3. 玩家入口和区域配置

主要入口仍在现有寻路限制编辑器。区域配置窗口只作为编辑器的辅助面板，不建立全局列车调度系统。

每个区域明确指定所属公司、区域编号和运行方向。用信号的角色绑定区域：

1. 接近检测/安全入口。
2. 正线分支控制信号。
3. 每股道的待避入口。
4. 对应股道的待避出口。
5. 汇合冲突区之后的出清确认信号。

不通过地理距离猜测哪些并列股道属于同一区，也不根据“上行、下行”等名称推断方向。不同公司的相同编号不混用。

区域参数：默认速度增幅 25%、检测范围 100 格、速度能力模式、连续待避/满载腾空开关、批次与防饥饿策略。旧存档没有新区域时完全不启用。

首期仅开放“编组最高允许速度”能力模式，保留有效区间速度接口。不得把还没实现的功率/重量/坡度估算显示成已可用功能。后续模型需采用确定性的整数计算并验证轨道、编组和已知区间限速。

## 4. 新条件及动作边界

建议用 7 个新条件对应需求 A～G，所有条件都是只读：

- 后方有符合条件的优先快车。
- 本车需要进入待避线。
- 本区存在适合本车的可用股道。
- 本车仍需等待关联快车。
- 本区适用股道全部占用/认领。
- 本车获选优先腾空。
- 本车允许解除待避。

GUI 显示区域名称和编号；百分比、距离等共用参数由区域面板维护，避免 7 条条件各自设置冲突参数。

新条件沿用 Is/Is not、IF/ELIF/ORIF/ENDIF；仍由玩家使用原有 Deny 和 Wait 动作。

需要少量“区域/信号角色绑定”元数据和正式提交接口。它们不等于允许在 Execute 的只读求值阶段创建关系。

正线示例：

    IF 本车需要进入待避线 [区域]
    AND 本区存在适合本车的可用股道 [区域]
        Deny
    ENDIF

待避出口示例：

    IF 本车仍需等待关联快车 [区域]
    AND NOT 本车获选优先腾空 [区域]
        Wait at path signal
    ENDIF

“获选腾空/允许解除”只能取消智能待避自身的限制；始终不能绕过其他程序、红灯、轨道占用或 PBS 检查。

## 5. 区域模型、检测和路线证明

区域维护有向拓扑，不硬编码股道数量。每条候选股道记录入口、出口、长度、轨道类型、方向、冲突段和出口出清边界。

- 用受限轨道遍历和车辆地块索引收集接近车辆，限制格数、分支和节点数。
- 仅处理当前区域附近的主列车；不在每次 YAPF 中遍历全地图 Train::Iterate。
- 空间接近和速度较快只是粗筛；必须证明后车的实际后续路径经过同一入口/待避区，方向一致，存在共同下游区间和安全分流机会。
- 先利用有效的既有预留/已知路线；证据不足时使用限预算只读路线探测。探测不可预留轨道、修改当前命令、认领股道或消耗随机数。
- 同步验证股道入口至出口的合法路线，而不是只检查某一格为空。保留所有原有路权、轨道类型及寻路限制。
- 需要防止“可用股道条件 → 寻路探测 → 同一可用股道条件”的递归。通过显式探测上下文与稳定的区域判定快照隔离，普通信号限制继续生效。
- 没有完成证明或超过探测预算时，结果是“不能确认”，不能据此强制 Deny。

速度比较采用 64 位整数乘法：后车速度×100 >= 前车速度×(100+增幅)，避免浮点和不同客户端速度单位的影响。

安全性与可行性分别判断：既有制动/预留已经锁定路线，或车已越过安全分流点时，不为新到快车重排。

## 6. 状态和正式提交

严格区分五类信息：检测记录、追越依赖、逻辑股道认领、实际车辆占用、PBS 预留。

列车在区域内的状态转换：

    接近 → 候选待避 → 股道认领已提交 → 已进入股道
    → 等待批次 → 出口预留已提交 → 车尾出清 → 已清理

“腾空候选”及“获准腾空”是等待阶段的分支，不代表已经驶离或股道已经可用。

只读条件根据一致的区域快照返回结果。正式预留成功、确认列车实际选择该股道后，才提交唯一认领。预留失败必须没有永久新增状态。提交阶段仍要复核认领，采用现有路签临时状态/回滚的事务思路，不能依靠试探顺序。

PBS 的实体路径互斥不能替代逻辑股道认领，逻辑认领也不能清除别人的 PBS 预留。认领一直保留到整列车驶离或证明确实失效。

缓存只保存可重建数据。影响放行的状态必须保存并参与同步检查；不得把客户端调用次数、UI、墙钟或无序容器遍历顺序作为决策输入。

## 7. 多列车与批次

依赖是多对多关系。例如 100 等待 160 和 200，200 出清只解除其中一条依赖，100 继续等待 160。

普通追越依赖只从较慢列车指向符合阈值的较快列车，这部分按速度严格单调；同速使用稳定的既有通过权、到达批次和持久身份排序。

- 对尚未提交不可取消通行权的同批次候选，可以重排。
- 对已经提交通行权的列车冻结决定，不能后来者强抢。
- 进入批次后冻结可插入集合，后来的快车参加后续批次，避免慢车无限等待。
- 防饥饿调整的是智能待避的优先级，仍须满足线路和 PBS 安全，不是到时间无条件放行。

目标通过顺序 200→160→100 和 240→200→160→100 只在路线、批次和既有预留允许时成立。

## 8. 满载腾空与死锁

入口 A=100、后车 B=200、股道内 C=160 时：

1. 确认 A 确有待避关系，且全部适用股道不可进入。
2. 在比 A 更快的股道列车中，按可执行出口路线、出清时间、股道容量和既有权利选腾空者。这里不机械套用 25% 阈值。
3. 只选择不会立即封住 B、且确能给 A 提供适用空间的方案。
4. A 在安全入口等待；C 仍通过普通 PBS 取得出站路线。
5. C 车尾离开股道和冲突区后，股道才交给 A；不能在批准 C 出站时就宣布股道空闲。
6. A 进入，B 通过，A 在 B 车尾出清后放行。

依赖图要包括“等待另一列车”“等待股道腾空”“受实体/PBS 阻挡”三种边，否则看不到 A→C→B→A 的环。

发现环时，优先寻找已证明安全的腾空方案；没有方案时放弃新增的逻辑待避/入口等待并重新评估。此处只撤销智能系统的逻辑限制，绝不直接清除 PBS 或让车闯红灯。

无法证明安全腾空，不得永久 Deny 所有路线。降级允许正常铁路规则决定通行，记录原因供诊断；不能宣称这种场景也保证理想超越顺序。

## 9. 清理、车尾和身份

正常出清使用实际车尾通过已配置的下游确认边界，结合实际占用和预留复核。仅车头到达出口、路签计数减少或认领过期均不足以释放冲突区。

事件钩子覆盖删除、掉头、进库、编组拆并、调度修改、路径改动、信号/轨道/区域配置修改和读档。事件清理必须幂等。

低频确定性复核只处理活动区域与活动列车，发现记录、实际方向、路线或区域布局不一致时重新验证关系。

VehicleID 可复用，不能只保存一个裸 ID 长期引用。需要持久参与代号/世代或等效的车辆生命周期身份，创建、读档和删除路径都要有测试。新客户端必须加载同一代号和序号计数，不能自行按本机注册顺序生成。

超时只触发复核和批次老化，不直接清除实体占用、有效预留或所有等待关系。

## 10. 保存、网络和兼容

- 区域配置及权威状态通过命令和扩展保存特性维护，给新增指令/参数增加必需的版本能力标记。旧版程序不能静默忽略新条件。
- 老存档缺少新特性时默认没有活动待避区域、状态为空，原程序求值不变。
- 读档先恢复权威状态，再统一验证布局、车辆身份和依赖；只读缓存重建后才能用于求值。
- 加入中的客户端必须收到和服务器一致的批次、身份、依赖和认领；不能仅同步配置却让客户端自行猜测现有批次。
- 稳定排序规则覆盖区域、股道、列车和依赖；使用游戏 tick，不使用本机时间。
- 修改信号程序、复制程序、蓝图旋转/复制、存档和网络反序列化均需识别新字段。
- 自定义机场不在本功能改动范围，但联机回归继续包含现有机场存档，避免扩大不相关修改面。

## 14. 路签关联与总开关（2026-10-19）

- 不再手动填写区域编号。接近、正线、待避入口、出口、出清点及相关条件均从现有下拉列表选择同一个普通列车路签；共享同一个路签对象的信号属于同一待避区域。
- 接近点沿用现有预留/回滚事务领取路签。路签遵守原有容量限制，应设置为足以容纳该区参与列车；股道独占认领继续使用隐藏内部路签，源路签在路签列表和车辆详情中正常显示。
- 手动将列车移出关联路签后，该车的七种待避条件（包括反向条件）均不成立，正线/股道/出口待避动作不再限制该车，并立即释放该车的内部股道认领。PBS 和实体占用仍保护轨道，取消不会删除轨道预留。再次经过接近点时可以重新登记。
- 车尾通过出清点后退出源路签并释放股道；车头通过不释放。开关关闭时仍允许出清清理，避免遗留占用。
- 总开关位于“高级设置 → 车辆 → 经由 → 寻路限制自动待避”，默认关闭。通过现有服务器设置命令同步并写入存档。关闭时不登记新成员、不执行待避限制，清除隐藏股道认领，保留普通路签成员供用户管理。
- 原编号版（`pxp_automatic_yield` v1）读档时复用已有隐藏检测路签，将其公开为普通路签并改写指令引用，保留既有列车成员和股道认领；v2 保存使用路签 ID，不改变旧特性的枚举编号。
- 状态索引是可重建缓存；每次低频清理只处理最多 16 个路签成员，窗口从存档中的游戏刻度推导。无效布局不分配内部资源。不以本机时间或本地公司参与运行判定。
