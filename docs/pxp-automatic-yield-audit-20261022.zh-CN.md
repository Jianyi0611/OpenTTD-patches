# 自动待避审查与修复（2026-10-22）

## 本次修复

### 1. 已预留越过正线标记时漏掉分岔前复核

187 号问题存档开始时已到 (1171,3982) 分岔并选定直行轨道。系统确实判断它需要给 189 号待避，但此时已不能从当前轨道转入侧线。

独立回归场景确认：慢车在快车登记前，预留已经越过正线标记、延伸到远处信号。旧代码只从预留末端向前寻找 Main，漏掉已经包含在预留中的 Main。修复前，同场景慢车不进侧线；修复后进入侧线、等待快车出清再离开。

新增受预算限制的只读检查，从车头沿连续的本车已预留轨道确认前方 Main。只有车头仍能进入合适空股道、且原有优先级要求待避，才调用现有 PBS 取消/重新预留流程。手动停车、强制闯灯、换向、连接作业、既有侧线认领等保护继续保留。

原始 187 号存档已经错过转入点，修复不会在车头下强行切换轨道，也不宣称它在这份存档里会原地回到侧线。修复针对后续尚未过岔的列车。

### 2. 前进路线检查不再穿过车库换向后绕回

原有几处几何跟踪会跟随车库的自动换向，可能把掉头后的线路当作当前前方的股道或合流路线。统一在车库处终止这类前进证明；目标预判原有“非目标车库不确定”的保护继续保留。实际列车回库、换向和寻路机制没有修改。

### 3. 未持签车辆仍消耗真实股道容量

入口的物理安全检查原本就检查所有车辆和预留，而位置分配曾直接使用空认领记录计数，腾位压力也可能只数已认领列车。

现在分配剩余位置和计算腾位压力时，都使用相同的可用股道证明，考虑整列车、其他公司的车辆、未领签车辆、手动取消路签后的车辆、换向/倒行车辆及其反向预留。车头已离开而车尾还占线，仍算占用；车还未到、路径已被另一列车预留，也不能当成空位。

这些车辆仅作为实际占用/预留障碍。不会因容量检查自动加入路签，不会被自动选为腾位对象，手动取消路签的控制权继续保留。每次检查读取当前状态，车辆出清或释放预留后可以恢复容量，没有额外的跨 tick 占用缓存。

同一路签仍共享股道容量，未新增按方向保留名额的规则。

## 仍需注意的边界

物理线路没有安全出路、车长不合适、检测点已在分岔之后，或外部手动车辆堵住全部出口时，自动待避不能通过无条件放行解决。共用轨道和未出清车尾仍按 PBS 互斥；不保证任意配置都不会死锁。

车头/车尾登记模式以实际越过检测点为准。若连续的“继续预留路径”要求先取得远处区间，可能在尚未越过检测点前被普通 PBS 拦住，此时不会擅自提前登记；需要提前识别时可使用“预留路径时登记”。
