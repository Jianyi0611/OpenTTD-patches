# 自动待避停车段统一判断（2026-10-22）

## 修复范围

此前已修复 202 / 197 存档的复合合流入口，但长度判断仍针对入口形状作推断。进一步检查发现：交叉轨道会让后方足够长的停车段被整体拒绝；显式入口与仅出口配置使用不同长度算法；弯道被按整格计长，可能高估停车空间。

本次将停车空间改为统一的物理轨道段判断，适用于普通待避线、站台及旧式入口配置。修改集中在 src/tracerestrict_overtaking.cpp；保留此前所有已完成的待避修复，没有修改原寻路器。

## 统一规则

1. 从待避出口逆向检查实际连接的轨道，只累计紧邻出口的独占停车段。
2. 道岔、交叉轨道是停车段的边界，边界整格不计入；入口中其他支线怎样连接不再决定后方独占段是否有效。
3. 同格但不相交的平行弯轨分别处理。直轨按 16、弯轨按 8 计长，与现有列车长度单位一致；不再用经过格数代替实际长度。
4. 出口信号格不计入，另保留原有一整格车尾余量；正线标记不能被重新解释成侧线停车空间。
5. 显式入口到出口的通行检查保留，并增加同一停车段证明。满线腾位、空位检查、仅出口认领和站台识别共用该几何判断。
6. 桥隧沿实际两端及跨越长度检查，不读取桥下地面作为轨道。几何长度证明不会替代原有整跨占用与预留检查。
7. 实际入线和离线仍检查方向、兼容轨道、普通寻路限制、其他列车、换向列车、无路签车辆、认领和 PBS 预留。

## 同步与性能边界

没有新增存档字段、网络命令、随机数或持久缓存。每次判断仍使用原有总计 1024 节点、单路线 256 节点的上限；站台与桥隧跳过的长度同样扣除预算。没有扩大扫描范围，也不遍历全地图猜测入口。

本次解决的是停车段识别这一类误判，不能据此保证任意布局永远不会出现其他问题。标记不完整、停车段太短、路线无法证明或预算耗尽时仍保守回退；已经错过入口的车不会被强制倒回。保存点里的 202 就属于已过入口情况。
