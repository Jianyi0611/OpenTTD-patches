# 自动待避：不同出口与目标提前预判

## 规则

同一个自动待避路签可以关联 1 至 16 个车尾出清点。每个出口各设一个出清点，应放在该区最后的共用轨道、交叉或合流区段之后。只有一个出清点的布局继续采用原来的判断入口。

先读取列车连续且确属本车的已预留路径。尚未预留到分岔时，辅助检查当前有效命令的车站、路点或指定车库：只有一个分支可以到达目标、其余分支均已确认无法向前到达目标时，才能提前确定分支。不读取未来条件跳转，不推进命令，不猜测对接车辆，也不把“最近车库”当作固定目标。

这不是按站名、直线方向或最短距离猜路。多个分支都能到达同一目标、出口之后重新合流、环线、非目标车库可能换向、未能检查的桥隧/站台或检查预算不足，都保留原来的待避规则。长线路可能仍需等实际预留确认出口，这是有意的保守回退。

确认不同出口后，还要核对到出清点之间的轨道和整列车的占用范围。共用线路、平面交叉及未出清的车尾仍按原规则等待。若当前目标位于出清点之前，不预测完成该目标后的下一条命令和行驶方向。

共用站台、普通待避线的容量、认领、停站作业、最慢车优先及 190 号来线的容量不足提前放行规则继续保留。辅助预判不代表强制改道或提前取得 PBS 放行权。

## 性能、存档与联机

辅助判断为只读拓扑检查，不调用另一个列车寻路器，不修改 YAPF 选路、路径预留、列车命令或路签成员。每次目标分支检查最多消耗 96 个节点，仍受原来每次判断总预算和分线辅助预算限制，耗尽时回退。轨道冲突比较采用排序后的线性比较。

预测只在本次判断中有效；同一 tick 修改目标后也会重新检查。未增加存档字段、随机数调用或跨 tick 的本地预测缓存。联机各端须使用相同程序版本。

## 验证

- Windows x64 Release 本地编译通过。
- 全部 422 项测试、16,469 个断言通过。新测试覆盖车站/路点/指定车库、最近车库、缺失目标、多分支可达、出口再合流、环线、长线路预算耗尽、非目标车库、共用车尾、区间内目标、同 tick 改目标，并检查命令、预留、路签和位置索引无意外修改。
- 原有两来线合流场景：三种登记时机、快慢车互换及重载共 12 次通过，完成 tick 与修改前一致。
- 两个独立出口场景：快慢车互换及重载共 4 次通过，没有为另一出口的快车额外停车。
- 本机服务器和两个客户端的短时验证：77 个共同 tick 的车辆/RNG/路签/预留状态摘要一致，未出现车辆位置索引异常。此项不代替所有 NewGRF、所有布局及长期联机验证。

原有 190 号存档已在分线基础修改阶段重放通过；新增“同一区域增加第二出口但竞争车辆仍用同一出口”的容量回归，确保不会漏掉原有提前腾位规则。
