# 同一路签多正线控制（2026-10-20）

## 设置方式

同方向的多个正线控制信号选择同一个普通列车路签，继续共用接近检测、待避股道出口和一个车尾清除点。每组支持 1～16 个正线控制点、1～16 个接近检测点、最多 16 条待避股道和 16 辆参与列车。线路须能够汇入同一清除点；独立上下行或互不汇合的线路应使用不同路签。

不需要重建原有单正线配置。普通侧线、站台股道、混合股道和旧入口布局继续使用已有设置。

## 判断与保护

- 原来验证要求正线控制点恰好一个，现改为 1～16 个。重复、缺少角色、超过上限等无效配置仍停用自动控制，不取得入线许可。
- 每辆列车使用沿当前方向最近可达的正线控制点及对应距离。已明确处于不同正线入口的车辆，不直接用各自距离推断前后关系。探路未完成的远处成员仍保留原有保守处理。
- 有同线后方快车时，优先确认是否存在另一条可安全经过的正线。需要从本车位置证明到达该正线，并从该点证明到共同清除点可通行。其他车辆、外部预留、轨道兼容性及普通限制均参与检查；同一路线上前后两个控制点不视为平行线路。
- 若先找到的备用正线下游被阻挡，会在剩余预算内检查其他分支。不能证明可用时继续原待避规则，不解除正常 PBS 保护。
- 共享出口的待避车辆仍保护同组快车通过，直到车尾清除；不会因快车使用另一正线就提前释放。腾位候选必须确实有同线快车追赶，防止另一正线的距离错误触发腾位。
- 原寻路算法和实际路径预留均未更改。可用备用正线仅用于避免不必要的强制待避，不保证列车一定选择该线路或实现最佳并行吞吐。

没有新增随机数、线程、本地 UI 判断或每帧全图扫描。路线检查仍共享每次 1024 节点预算、单次搜索 256 节点；额外的平行线路偏好检查最多使用剩余预算的一半且不超过 256 节点。仅对确有快车威胁的候选进行额外检查。

## 存档与联机

指令编号、参数布局、路签和隐藏股道记录格式不变。运行缓存中的正线数量由存档指令重建。特性版本升为 `pxp_automatic_yield` v7，继续读取 v1～v6；旧程序拒绝新版存档，避免悄悄忽略多正线规则。联机请统一使用同一新版。

## 站台腾位的具体含义

不是只要发现“快车前方有正在停站的慢车”就放走待避车辆。只有更慢的来车受同线后方快车追赶、没有合适空股道，并能证明某辆待避车离开后它可安全进入和离开该股道，才提出腾位。候选待避车必须比这辆来车快；从符合条件的候选中优先选择最高速度最高者，同速按稳定车辆 ID 排序。

例如待避线上有 120 和 160 的车辆，进区来车为 80，其后有 200 的快车，所有合适待避股道已满：若离开路线和来车接替路线可用，可以优先让 160 的车辆先走，为 80 的来车腾出对应股道。并不保证一定放走全组最快车：它若正在装卸、等连接、受其他预留阻挡或不能安全腾位，会跳过。

已经在站台执行停站作业的慢车不会仅因处于快车前方就触发上述腾位；不会提前结束装卸、停站等待、解挂或连接任务。站台侧线已完成作业、只是受自动待避出口限制而等待的车辆，仍可参与符合条件的腾位。正在通过的快车及车尾未出清的快车继续受到保护。
